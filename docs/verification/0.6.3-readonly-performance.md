## 选择与实现

诊断、调用树、符号搜索和 Git 是主要耗时项。固定 SDK 的批量诊断使用项目级 mainPassesMutex，涉及共享 Daemon 状态和写操作协调；没有通过并发绕过互斥、缩短等待、缓存空结果或删除检查来提速。其他三项仍保留官方算法，本轮未发现可以安全独立替换且稳定通过门槛的方案。

实际实现针对公共分派开销：

- Backend 和 PlatformToolProvider 增加按名称查询描述及 prepare 默认接口，旧 lambda / 只提供 tools/call 的实现继续兼容。
- OfficialMcpAdapter 只转换请求目标的描述/schema，省去协议和分派阶段重复转换完整目录；tools/list 仍生成原有完整并集。
- 在单次请求内传递描述及提供方调用闭包，执行前检查提供方仍注册；官方 call 仍重新取得当前筛选后的工具并校验当前 schema。长操作在真正执行的工作线程上做这些检查。
- 不新增结果缓存、目录缓存、授权缓存或 ThreadLocal；不改变原生语义、工具数量、输出字段、搜索范围、异步最终结果或确认设置。

这是对同一官方实现的分派整理，没有新增或替换工具算法。

## 同层复测与启用依据

独立 IDEA 沙盒复制本项目 src，建立真实 Java 源根并添加真实 tomlj JAR 依赖。两组使用同一个项目和相同 HTTP/RPC 服务配置：优化后的真实 IdeaToolBackend，与重现 0.6.2 两次完整目录转换的对照后端；底层均为相同的真实官方提供方。对照重现的是本插件原分派流程，**不是官方独立 HTTP 传输端点**。

六个单项各预热两轮、交替测量 20 轮。源码读取仍为完整 Arguments.java，目录树包含全部复制的 src 内容，符号搜索仍返回三个位置。沙盒为一个模块和一条显式第三方依赖，依赖查询明确要求非空；不把该夹具冒称为生产项目的 446 条依赖负载。

公共分派优化进一步以预先补充到设计中的真实“项目概览”组合任务验收：并发执行全部模块、全部依赖、完整源码和完整目录树四个请求，**四份结果全部返回后才停止计时**。同样两轮预热、20 轮交替测量，不将单请求中位数求和冒充任务耗时。

| --- | ---: | ---: |

中位数减少 **2.2911 ms / 33.8%**，P95 减少 **50.1%**，完整结果及大小一致，满足该组合任务的门槛，因此保留公共分派优化。它主要减少连续或并发短查询的固定开销，不等于诊断、Git、调用树算法显著加速。

某次中间复测曾出现目录树 P95 较高，因此保留该记录并另加 **80 轮/组**尾延迟核验。最终补测原分派中位数/P95 为 **4.93 / 6.05 ms**，新分派 **3.86 / 4.42 ms**，结果全部一致；没有依赖删除离群样本来满足门槛。

最终同层记录包括 240 个单项样本、40 个项目概览样本及 160 个目录树尾延迟样本，共 **440 条测量记录**。其中每个概览样本包含四个实际请求，正式共 **560 个 HTTP 请求**；含预热共 **600 个**，全部完成完整响应比较。JSON 全字段、文本、结果顺序与响应大小均一致。计时使用 System.nanoTime，包含发送与完整响应接收，断言比较在计时后完成，不包含模型或整个 Codex 调度。

数据位于 `build/benchmarks/063-tool-lookup/`：`sandbox.json`、`summary.csv`、`source.json` 及各阶段原型记录。计时器及原分派对照保存于 `OfficialMcpAdapterTest.testSameLayerNamedLookupBenchmark`，通过 `-PrgExecutable=<rg.exe绝对路径>` 显式启用。

## 后续方向

优先继续剖析调用树的索引/层级构建阶段，以及诊断的互斥等待、主检查和写操作重试，使用非空错误/警告夹具；保留官方完整树与检查配置。Git 状态需单独区分进程启动、仓库扫描和结果解析，不能以旧状态缓存减时间。文本与正则目前较快，未达到改写完整 IDE 搜索语义的依据。新版本生产调用的收益仍需安装后按本轮相同任务实测。

## English

Thirteen equal-result production baselines cover file/text/regex/symbol queries, full trees, dependencies/modules/VCS/Git, documentation, diagnostics, batch lint and a complete one-level incoming call tree. Expensive algorithms remain official; no mutex, checks, results or fresh state were bypassed.

Version 0.6.3 resolves the requested descriptor and reuses its provider within one request, rechecking live availability and schema at execution. There is no result/catalog/authorization cache. Controlled isolated HTTP tests found roughly 1.1–1.8 ms per-call savings, insufficient to claim an independently replaced tool meets the established median gate. A separately designed four-query project-overview task, returning every full response, improved from **6.78/9.65 ms** median/P95 to **4.49/4.82 ms**: **33.8% / 2.29 ms** median reduction. Its output remained 8,620 characters. Eighty extra tree rounds checked the earlier tail variance. These are comparisons against the old adapter dispatch behind the same HTTP wrapper, not the official standalone endpoint or production Codex timings.

All **83 tests**, **94 protocol assertions**, isolated Codex integration, packaging and structure checks passed at build time. The user subsequently installed 0.6.3 and passed [production verification](0.6.3-installed.md). The later audit found coupled ordering in the earlier twelve production and six sandbox single-task timings; treat those small differences as exploratory. The separately alternated overview and tree-tail measurements are unaffected. The benchmark expression has been corrected and final production measurements use balanced provider order. The ZIP and checksum are unchanged.
