## 目录树候选与保留边界

固定 SDK 的 FileToolset.list_directory_tree 使用真实磁盘遍历；每个节点重复
File.isDirectory，子项按 name.toLowerCase(Locale.ROOT) 稳定排序。
新 DirectoryTree 使用 DirectoryStream 和本次 BasicFileAttributes，保持完全相同的
绝对根、Unicode/emoji 名称、排序、缩进、目录斜线、深度、返回字段和 content 文本。
不使用 VFS 缓存代替磁盘，不过滤 excluded、ignored、点文件、未刷新或生成文件。

入口位于当前真实官方目录、动态禁用/路由和 schema 校验之后，并要求 fullyQualifiedName
精确匹配官方目录提供方；同名替换提供方继续执行自己的实现。
可立即取得短读锁时，先检查 VFS 中已缓存且已加载的根子项数；不足 32 则直接走
官方磁盘遍历，不进行额外磁盘资格探测。锁和缓存检查不覆盖 IO，也不刷新 VFS。
其他情况的根名称预探测达到 32 项即关闭流；少于阈值直接回退。这个阈值仅选择执行路径，
不是结果上限；合格目录仍返回全部节点。瘦根下的大树可能继续使用官方路径。
遇到链接/junction、非普通文件、排序键冲突、IO/访问异常、目录身份/时间变化、
超过 200 ms 候选预算或请求余量等，丢弃候选并回退官方；取消不变成成功。
磁盘遍历不持有 IDE 读锁，不保存编辑文件，不缓存跨请求结果或权限。

最初不带宽度选择的原型：4096 文件大树两轮 HTTP 中位数约 222～224 → 125～126 ms，
但 src 小树约 5.3～5.6 → 8.2～8.6 ms，明显回退。因此没有直接启用。
收紧后 40 对探索中，大树 HTTP 中位数约 211～213 → 119～120 ms；
小树中位数差约 0.2 ms，最大小树 P95 回退约 8.2%。首次原型和探索数据均保留。
发布前提高到每方 80 次复核最终代码，下面以最终复测为准。

最终同层复测：两端都是同一独立 IDEA 项目、同一个 HTTP/RPC 包装，底层对照是
真实官方提供方，候选是 0.6.7 适配器。这里不是官方独立 HTTP 端点与生产 Codex 的耗时，
不能把生产表和本表混算优化比例。每条件每方 3 次预热、80 次正式，独立两轮，
每方各先 40 次；每轮结果全对象一致，树正文逐字符一致。不删除最大值。

小树复制真实项目 src（63 个文件），双方共享已加载的 src 根 VFS 缓存；
大树为 32 个目录、4096 个普通文件，完整返回 **4129 个节点**，无需用 VFS 替代结果。
两个树的 maxDepth=100、timeout=10000，所有参数与输出规模在各自实验内不变。

## English

Git status is unchanged. Eighteen equal-result production tasks were screened against the
actual official MCP endpoint, with 1584 complete-result checks. The selected optimization
uses fresh NIO enumeration for complete disk trees with at least 32 direct root entries.
Thin roots and unsupported cases retain official traversal. An initial small-tree regression
was preserved and addressed before release validation. Controlled sandbox measurements use
the real official provider behind the same HTTP/RPC wrapper; they are separate from production
endpoint timings and do not establish post-install performance for the new package.
