## 当前 Codex 同条件速度复测

任务沿用此前文件枚举输入：`q="**/*.java"`，`paths=["src/main/java/**","src/test/java/**"]`，`includeExcluded=false`，`limit=1000`，明确指定本项目完整路径。

三种方式都在当前生产项目查询完整的 **48 个文件**。先两轮预热，再各 20 轮，六种调用顺序交替；66 次结果全部与磁盘完整路径集合相同，无重复、无截断、无部分结果。源码前后 SHA-256 逐项一致。正式样本 60 个，失败 0。

| 方式 | 中位数 ms | P95 ms | 文件数 |

| 当前 Codex → idea-java 0.6.2 | **7.5** | **9** | 48 |

idea-java 相对当前官方连接的中位数减少 **96.1%**，约 **25.5 倍**；P95 同时降低。两组 MCP 完整工具响应的 JSON 序列化大小均为 7,464 字符，没有通过缩减字段或结果数取得优势。

计时使用调用方 `Date.now`，包含 Codex 工具分派、查询及工具响应返回，排除模型思考与调用完成后的结果比较。Shell 列包含每次独立启动 PowerShell、rg、输出处理和工具返回；其进程内查询体中位数另为 **28.33 ms**，不能与整列耗时混算。基准复用已忽略目录中的 `061-equal-scope/shell-baseline.ps1 -Case files`，命令及结果范围与此前生产对比一致。

本轮数据与[独立沙盒中的 HTTP 对照](0.6.2-file-enumeration.md)计时层不同：沙盒为 3.34 / 15.73 / 29.10 ms，本轮才是当前聊天实际工具连接的测量。两组分别报告，不把其绝对耗时混在同一表中计算收益。

原始数据、66 次完整性检查、计时函数及前后源码摘要保存在已忽略目录 `build/benchmarks/062-installed/`。本次只做安装后只读验证和文档更新，未修改插件代码或重新打包；已验收的 0.6.2 安装包及校验值保持不变。
