## 保持的范围与测量方法

Git 参数固定 includeUntracked=true、includeIgnored=false、limit=10000，不指定单独选根；
不缓存、不删除慢样本、不减少条目。生产首组完整 **1 仓库 / 59 项**；
开发后客户端 A/B 与诊断完整 **1 仓库 / 64 项**。数量变化来自新增文档、源文件和脚本，
每个独立实验内部始终保持同一完整返回对象；不跨 59/64 项实验声称速度提升。

前序固定 dev.ideamcp.protocol.Arguments.required 的完整 **14 节点** INCOMING_CALLS，
depth=1、maxChildren=200、maxNodes=10000、childOffset=0、timeout=10000。
有前序时，每一个 Git 样本之前都单独重跑同一个官方完整调用树并等待返回，
双方各自施加前序，而不是一对只执行一次。前序与 Git 之间没有人工等待或其他查询。
同轮比较整个 MCP 对象，包括 content 文本、structuredContent、isError；
只忽略对象键顺序，保留数组顺序。检查条目数=totalEntries、hasMoreEntries=false，
拒绝树截断、部分结果与错误。不用重试替换失败样本。

生产首组与客户端 A/B 分别每条件每方预热 3 次、正式 80 次、各先 40 次，
两轮独立预热并反转条件顺序。沙盒每条件每方 84 次、三方全部六种排列各 14 次，
每方每个位置各 28 次、每对先后各 42 次。基准、构建及诊断录制不并发运行。
P50 为两个中间值平均，P95 用 nearest-rank；不据 80/84 个样本可靠估计总体 P99。

生产首组 58 个源码/资源文件前后 SHA-256 一致；客户端 A/B 的 61 个文件也一致。
项目测量前后 indexing=false，文档最终总结在实验结束后才写入。

### 独立诊断：发送前进一步定位

Node **24.19.0**、内置 Undici **7.29.0**。
另做每客户端 20 个固定官方前序 Git 样本，加预热 **92 次完整结果校验通过**。
诊断通道只读请求对象的身份及单调时间，不读取/记录认证头、参数、响应头内容或输出；
这批带诊断订阅的样本与前述公平实验分开。

fetch 的计时从 API 调用前起算：

| 阶段 | P50 | P95 | max |
| --- | ---: | ---: | ---: |
| 请求对象创建通知 | 0.361 | 0.505 | 0.727 |
| 即将向 socket 写请求头 | 3.778 | 11.968 | 14.004 |
| 请求体发送完成通知 | 4.114 | 12.187 | 14.430 |
| 收到并解析响应头后的 API 返回延迟 | 0.142 | 0.308 | 0.309 |
| API 返回后正文与解析 | 0.233 | 0.340 | 0.344 |
| 请求体发送完成至解析响应头，扣除已测服务端阶段后的残差 | 0.421 | 0.668 | 0.782 |

最后一行是**逐个样本**计算后再取分位数，不是两列 P95 相减。
[Undici 官方通道定义](https://github.com/nodejs/undici/blob/main/docs/docs/api/DiagnosticsChannel.md)
将 sendHeaders 定义在首字节写入 socket 之前，headers 定义在收到响应头之后。
因此已能将这批较大未覆盖成本定位到**客户端请求创建至发送前路径**。
尚未区分连接池调度、连接准备与事件循环等待；不能认定是某一个具体 Undici 缺陷，
也不能用 Node 的诊断代替当前 Codex 客户端内部诊断。

### HTTP 完成边界

开启计时后，头部新增 http_executor_wait、http_task_to_handler、http_admission 与
X-Java-Mcp-Timing-Id。响应头发出后才完成的阶段，由同序号 JFR 事件提供，
没有伪装成已在当前 Server-Timing 头内测到。
完成事件在请求关闭后瞬时提交，耗时读取各 Timespan 字段，而不是事件本身的 duration。

当前适配器每组 n=84，单位 ms：

| 轮次 / 前序 | HTTP 任务排队 P95 | 任务开始到 handler P95 | 响应头准备 P95 | 发送头 P95 | 正文写入 P95 | close P95 | 客户端残差 P95 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 / 无前序 | 0.033 | 0.155 | 0.034 | 0.131 | 0.004 | 0.142 | 0.853 |
| 1 / 完整调用树 | 0.025 | 0.109 | 0.042 | 0.072 | 0.005 | 0.151 | 0.794 |
| 2 / 无前序 | 0.024 | 0.108 | 0.028 | 0.074 | 0.002 | 0.150 | 0.775 |
| 2 / 完整调用树 | 0.027 | 0.082 | 0.020 | 0.066 | 0.001 | 0.130 | 0.619 |

客户端残差逐个请求用客户端时间减去事件 taskThroughClose 得到；
它还包含请求任务提交前、JDK 返回后的处理和客户端工作，不命名为纯网络。
close 有可能晚于客户端收完，其他环境中负残差也不强制归零。
本组结果没有显示 HTTP 队列、头/正文发送或 close 存在十几毫秒的常态瓶颈。

80 对开关对照（同一轮、顺序平衡）：

与旧 HTTP 边界相比，新观测在两轮无前序/固定前序中没有达到 10% 的 P95 退化，
也没有把小幅波动称作执行提速；不据此保证所有环境开销都为零。

## 实现、隐私与优化选择

- 计时关闭时保持原执行器，不创建计时上下文；开启才包装任务并保存线程局部数值，
  finally 恢复/移除任务上下文。认证与协议头校验成功后才返回观测。
- JFR 自定义事件默认 disabled，不主动开始录制、不落日志/磁盘。
  配置与脚本为 scripts/http-timing.jfc、scripts/record-http-timings.ps1。
  自定义字段仅固定数值和 responseCompleted，不保存工具名、JSON-RPC id、参数、路径、
  输出、认证或启动信息；不录制调用栈。请求序号只在当前 IDE 进程内关联。
- responseCompleted 只表示正文/响应写完且 exchange 正常关闭，
  **不表示 HTTP 2xx、MCP 工具成功或业务健康**。未经过的阶段为 −1，不伪装成 0。
  脚本的最小配置请求启用自定义事件；本轮 HttpCompletionTest 与 sandbox-http.jfr
  验证该配置的独立录制没有其他类型的事件，等待栈诊断另行录制。
- Git 服务替换、命令识别反射、等待栈录制仅在独立测试中，发布包不含 GitCommandProbe。
  查询正文、目录、Host/Origin/Bearer、严格 JSON、1 MiB 请求限制及 20 秒查询预算保留。

**没有采纳新的执行优化。** 没有请求内重复命令可删除；
命令终止通知后的 P95 只有约 0.17～0.32 ms，未发现修改 50 ms 取消检查轮询的收益。
Git 生命周期尾部仍需进一步区分操作系统执行/退出与 IDE 输出及终止交接。
HTTP 阶段也不支持重写序列化或发送栈；生产独立基准已改为原生 HTTP 记录，
但这不构成插件运行路径的优化。没有修改整个 IDEA 的 TCP_NODELAY 或全局调度设置。

候选继续沿用两轮门槛：P50 至少 20% 且 2 ms，或目标 P95 至少 20% 且 5 ms，
并满足中位数/无前序/多根基线退化限制。当前证据不足以安全替换官方 Git 语义，
因此交付更细的观测能力，保留真实完整结果。
