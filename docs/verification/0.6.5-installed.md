## 固定任务、完整结果与取样

项目：`D:/common-workspace/mcps/java-idea-mcp`，IDEA 2026.2.3 / 262.10968.63。
按[设计](../design/mixed-git-tail-latency.md)固定每个 Git 样本的独立前序：

| 任务 | 双方相同参数及完整范围 |
| --- | --- |
| Git | includeUntracked=true、includeIgnored=false、limit=10000、不指定单独选根；完整 **1 仓库 / 56 项** |
| 前序调用树 | symbolFqn=dev.ideamcp.protocol.Arguments.required、INCOMING_CALLS、depth=1、maxChildren=200、maxNodes=10000、childOffset=0、timeout=10000；完整 **14 节点** |

三组依次为：无调用树前序、每次先执行官方调用树、每次先执行 idea-java 调用树。
有前序时，在每一个 Git 样本之前重新执行同一完整调用树并等待返回，包含一对中的第二方；
不是只在一对之前运行一次。每组每方预热 3 次、正式 **80 次**，轮次奇偶交换顺序，
每方各先执行 40 次。全程串行，没有并发被比较查询、构建或沙盒运行。

耗时从当前 Codex 调用工具前到返回后结束，包含工具传输，不包含模型生成文字的时间。
逐次比较整个 MCP 返回对象，包含 content 文本、structuredContent 与 isError；
仅忽略对象字段顺序，保留数组顺序。Git 必须 entries.length=totalEntries、
hasMoreEntries=false；调用树拒绝省略、超时与部分结果。没有丢弃慢样本或重试掩盖错误。

正式 **480 次 Git + 320 次前序查询**；含预热 **830 次完整结果校验全部一致**。
58 个源码/资源文件的前后路径和 SHA-256 完全一致，报告与 README 在测量后才更新。
此前 0.6.4 固定前序生产测量为 51 项 Git，本轮为 56 项；双方本轮均取 56 项，
没有缩小到旧结果数，也不能直接把跨版本数值差异归因为代码加速。

单次慢样本仍存在，不能宣称尾延迟已解决。80 个样本的经验 P99 等于最大值，
不足以可靠估计总体 P99。本轮每个条件只运行一轮，不能据此确定长期回归或加速。

当前只有一个 Git 根，仍走官方回退路径；多仓库并行优化的沙盒收益不能套用于本项目。
0.6.5 未采用 IO 调度候选，生产复验也不支持新增缓存、缩小结果或替换官方 Git 语义。

## 分段计时边界与下一步

上述固定前序测量验证了端到端耗时与默认关闭行为，**没有取得生产内部阶段数据**，
不能把此前沙盒的 git_process / git_command_total 结果当成本轮生产证据。
生产观测需要在 IDEA 自定义 VM 选项加入 `-Ddev.ideamcp.timings=true` 并重启 IDEA；
开关在 HTTP 服务构造时读取，仅重载客户端工具目录不能启用它。本轮未修改 VM 选项或重启 IDEA。

启用后可在同样的固定前序条件下读取认证响应头，检查 adapter_dispatch、
adapter_provider_total 等阶段。`*_total` 与子阶段重叠，不能全部相加；
生产包不提供沙盒专用的 Git 命令/进程探针。当前数据不足以把慢样本归因为调度、
Git 子进程、系统扫描或 GC；应先补充生产阶段证据，再决定是否修改实现。

原始样本与核对产物位于忽略目录 `build/benchmarks/065-installed/`：
production.json、production-summary.json、connection.json、http-git-check.json、
source-before.json、source-after.json。没有操作业务 Run/Debug 会话。
