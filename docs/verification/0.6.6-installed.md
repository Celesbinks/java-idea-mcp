生产项目为 D:/common-workspace/mcps/java-idea-mcp，完整 **1 仓库 / 65 项**状态。
Git 参数固定 includeUntracked=true、includeIgnored=false、limit=10000，
不指定单根筛选；每次检查 entries.length=totalEntries、hasMoreEntries=false。
前序固定为官方 analyze_calls：dev.ideamcp.protocol.Arguments.required，
INCOMING_CALLS、depth=1、maxChildren=200、maxNodes=10000、childOffset=0、
timeout=10000，完整 **14 节点**，拒绝截断、部分结果及错误。

混合条件下，每一个 Git 样本之前均单独重跑相同官方完整调用树并等待返回，
双方各自施加前序，前序与 Git 间没有其他 MCP 查询或人工等待。

只规范化对象键顺序，保持数组顺序。没有重试替换失败样本或删掉慢样本。

双方使用同一 Node 24.19.0 原生 HTTP 客户端，读取现有 Codex 连接配置，
复用连接并维护官方后台事件流；计时从发起请求到完整 JSON/SSE 正文解析完成，
不包括结果比较。这个对照衡量当前生产端点，不包含 Codex 自身的工具调度与 UI 延迟。

## 生产 JFR 完成事件关联

仅对已确认路径的 IDEA 进程 36128 启用 scripts/http-timing.jfc 中的
dev.ideamcp.HttpRequestCompleted；不用通用 profile、Git 命令探针或等待栈探针。
本次录制设 180 秒自动结束，并在查询完成后仅停止自己创建的录制。
开始和结束检查均无其他活动录制，没有遗留录制。

独立诊断轮每条件每方预热 3 次、正式 40 次，先后各 20 次，范围和完整返回不变。
**160 个正式 Git、258 次完整结果校验全部通过**。
取得 **88 个完成事件**：80 个正式 idea-java Git、6 个预热 Git、初始化及通知各 1 个。
全部 responseCompleted=true，无重复序号；86 个 Git 的响应头序号均匹配自己的事件，
公共阶段头值与事件的误差均小于头部 0.001 ms 的截断精度。
只按数值请求序号关联，事件不含工具名、路径、参数、正文或凭据。
