## 原因与修复

1. 0.6.0 固定使用 `DIRECT_WITH_ROUTER_ENABLED` 获取目录。SDK 工具默认 `enabled=true, routerOnly=true`，而 IDE 默认会话为 `DIRECT`。官方 `DIRECT` 模式仍展示这些工具；只有启用路由模式时才从直连目录隐藏。固定模式导致默认安装只能展示路由工具。
2. 官方 `execute_tool` 从调用上下文取得 `McpSessionHandler` 及其实际筛选提供方。0.6.0 未附带该对象，导致提交后的路由失败。
3. 0.6.0 的集成测试显式把工具设为 `routerOnly=false`，没有覆盖真实默认行为。测试现改为清空测试沙盒覆盖值，验证 SDK 原始默认值，并还原模式/设置。

0.6.1 跟随 `McpToolFilterSettings.invocationMode` 选择官方过滤模式，仍启用所有筛选提供方；为路由创建无网络传输的 SDK 服务及官方会话上下文，结束时清理自身协程/监听。用户工具禁用规则和命令确认设置保持有效，原生查询仍不经过官方目录。`McpExpectedError` 保留为 MCP 工具错误及异步最终 `result`，不再仅留下异常类名。

Managed Codex configuration ownership matches and no automatic-update error is recorded. Native symbols, official module/file queries and routed module queries succeeded; the routed operation reached `completed` with `result.isError=false`. PSI-tree generation, inspection API documentation and inspection examples also succeeded. This was a read-only verification, not an execution test of every mutation tool.
