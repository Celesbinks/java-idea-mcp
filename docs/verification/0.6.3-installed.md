## 方法与顺序更正

输入沿用此前十三项只读任务，另保留已优化的文件枚举作为回归对照。每项两轮预热、20 轮正式测量；查询同一项目、相同输入和完整结果范围。每轮旋转任务顺序，提供方先后**仅由轮次奇偶决定**，与任务位置独立；已从实际记录验证，每个任务两种提供方各先执行 10 次。

本次首轮检查发现旧计时器把任务位置与轮次同时用于提供方顺序。任务数为偶数时，两种轮换相互抵消，使每个任务固定先由同一方执行，可能使第二方受益于热缓存。首轮 560 条正式样本已保留为 `order-biased-first-pass.json`，**排除出本报告最终统计**，随后重新预热并完整采样。完整结果比较在该首轮也通过，问题在计时先后公平性。

同样的问题影响此前十二项生产基线及六项沙盒单项轮换，其细小差异应视为探索记录，不能作为严格公平的速度证据。此前独立采样的调用树、按轮次交替的项目概览和目录树 80 轮补测不受此问题影响。本次更正了测试源码中的相同轮换表达式，仅影响基准工具，不改变插件代码或已安装 ZIP。

时间使用调用宿主 Date.now（1 ms 分辨率），从 tools.* 调用到完整返回，排除模型推理及返回后的比较。逐次比较所有字段和完整文本，数组按集合排序比较；拒绝截断、部分结果、超时或未分析状态。读取检查全部 39 个编号行及末尾空行；文件枚举另与磁盘全部 Java 路径集合核对且无重复。51 个 src 文件的 SHA-256 在整个测量前后逐项一致。

## 完整四查询项目概览

并发调用全部模块、全部依赖、完整 Arguments.java 和完整 src 树，四份响应全部返回后停止计时，再分别与上述完整期望结果比较。每组两轮预热、20 轮正式样本，先后每轮交替；每个任务组均使用同一个提供方。

| 项目概览 | idea-java 0.6.3 | 官方 MCP |
| --- | ---: | ---: |
| 中位数 / P95 | **13 / 14 ms** | **14 / 19 ms** |
| 四份工具结果 JSON 字符总数 | **71,134** | **71,134** |

本轮中位数约省 **1 ms / 7.1%**，P95 约降低 **26.3%**。它包含当前 Codex 工具分派和完整的生产依赖列表，没有复现此前同层沙盒的 33.8% 改善。此前沙盒对照为原适配分派、仅一条显式依赖；本轮对照为官方真实 MCP 端点且含 446 条依赖，不能混算为同一优化比例。

文件枚举相对官方本轮中位数约降低 **97.2%**（约 **35.9 倍**）。其他小查询多为 0～2 ms 差距；语义搜索、诊断、批量检查及调用树没有证实显著提升。模块和 Git 的 P95 本轮较高，不能宣称所有工具尾延迟均改善；20 个样本不足以对整个运行期作稳定性保证。

最终单项正式样本 **560 条**；项目概览正式样本 **40 组**、每组四个实际请求，合计正式工具调用 **720 次**。含预热，共 **792 份工具结果**通过完整比较；全部测量调用无错误。首轮顺序有偏的样本独立保留，不计入上述数字。额外的连接、路由和回退查询另计。
