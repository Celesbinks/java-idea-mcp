## 生产：给每个样本独立施加同一前序

在已安装 0.6.4 的两个真实 Codex MCP 连接中测量。
Git 参数固定为 includeUntracked=true、includeIgnored=false、limit=10000，不指定选根。
测量时完整 **1 仓库 / 51 项**，双方相同；没有截到此前的 49 项。
前序固定为完整 **14 节点** Arguments.required 入向树，depth=1、maxChildren=200、
maxNodes=10000、childOffset=0、timeout=10000。

每次取 Git 样本之前都重新执行并等待前序返回；不是一对 Git 之前只做一次。
无前序、官方前序、idea-java 前序三组独立，每组每方预热 3 次、正式 80 次，双方各先 40 次。
逐次比较整个 MCP 返回对象（正文文本与结构化数据），仅忽略对象字段顺序，保留数组顺序。
拒绝截断、部分结果和错误，未删除慢样本。正式 480 个 Git 样本与 320 次前序查询，
含预热 **830 次完整结果校验全部一致**。55 个源码/资源文件的前后 SHA-256 完全一致。

单位 ms；P50 为中间两项平均，P95 采用 nearest-rank。

| 每次 Git 前序 | idea-java Git P50 / P95 / max | 官方 Git P50 / P95 / max |
| --- | --- | --- |
| 无调用树前序 | 62 / 76 / 88 | 62 / 72 / 93 |
| 固定官方完整调用树 | 71 / 85 / 131 | 71.5 / 83 / 96 |
| 固定 idea-java 完整调用树 | 71 / 83 / 132 | 73 / 84 / 101 |

官方前序在两种 Git 目标前的 P50 分别为 572/570.5 ms，idea-java 前序为 618/617 ms，
均为同一语义范围的真实查询。前序保持一致后，双方 P95 更接近；该结果支持原混合轮测
存在前序负载混杂的判断，但不能只由这些毫秒数据确定慢样本的内部原因。
80 个样本的经验 P99 就是最大值，未据此估计稳定总体 P99。

## 沙盒：固定负载与三方平衡对照

独立 IDEA 2026.2.3 / 262.10968.63、JDK 25、Java 21 字节码。
复制项目主源码、使用真实 JDK 索引与真实官方调用树；临时 Git 仓库包括暂存/未暂存修改、
中文空格重命名、未跟踪及忽略项。每次 Git 前同样执行官方完整 14 节点树，另测无前序对照。
没有用人工占满线程池的负载证明收益。

三方为官方 SDK 同层封装、当前 Default 适配器、仅测试构造器注入的 IO 候选。

每个位置各 28 次，任意两方互相先执行各 42 次；每轮重新预热，保留全部样本。
共 **1008 个正式 Git 样本**，所有完整结果相同。沙盒依赖和仓库规模较小，绝对值不能外推生产。

## 分段结果与边界

通过请求独立的计时上下文与 Coroutine ThreadContextElement 跨线程传播，响应头直接
关联客户端样本；不从不同请求的时间差推算阶段。Git 服务代理只在测试 IDE 注册并自动恢复，
给真实 GitLineHandler 附加公开生命周期监听；不记录命令行、环境或输出。

固定前序、当前 Default，两个正式轮次的阶段 P50 / P95，单位 ms：

| 阶段 | 轮次一 | 轮次二 |
| --- | --- | --- |
| RPC prepare | 0.112 / 0.244 | 0.089 / 0.122 |
| 当前 schema 校验/转换 | 0.027 / 0.067 | 0.024 / 0.045 |
| Git 根范围检查 | 0.009 / 0.026 | 0.006 / 0.008 |
| 提交到首次进入协程 | 0.024 / 0.034 | 0.020 / 0.025 |
| 提供方与返回交接总时间 | 61.92 / 81.88 | 52.16 / 58.16 |
| Git.runCommand 总时间（仅测试） | 61.39 / 81.02 | 51.74 / 57.70 |
| Git 生命周期回调区间（仅测试） | 52.30 / 71.87 | 45.50 / 50.23 |

这些阶段有嵌套，分位数也来自不同样本，不能相加或相减还原精确总成本。
首段排队没有覆盖 SDK 内部所有挂起/恢复，提供方总时间则包含这些成本。
Git 处理器在进入服务代理以前已构造，本次未直接测得其构造时间；缺失值不能记为零。
Git 命令与生命周期回调之间的差额不能直接认定为启动或锁等待。

最终轮次一个慢样本：客户端 **106.21 ms**，提供方 102.65，Git 命令 101.01，
生命周期回调区间 90.53，首段排队 0.052 ms；该样本检测到 GC 时间增量 5 ms。
更早的探针有 134.09 ms 样本，Git 回调区间 126.90 ms、首段排队 0.036 ms，
未检测到 GC 计数增量。均保留，不能因为 GC 或慢而剔除。
观察将主要成本缩小到官方 Git 命令范围，但尚未区分进程创建、文件扫描、系统调度和 GC
的独立贡献，也未证明这就是生产中 131～132 ms 样本的原因。

## 0.6.5 的可选诊断能力

默认关闭。用户需要采样时可在 IDEA 自定义 VM 选项中添加
`-Ddev.ideamcp.timings=true` 并重启 IDEA；本任务未替用户修改 VM 选项或重启 IDE。
认证成功的 HTTP 响应包含 `Server-Timing`，只有固定阶段名与毫秒耗时，不含参数、
路径、令牌、用户环境或业务输出，不写日志，不增加 MCP 工具或修改响应正文。

运行时头部覆盖请求读取/解析、RPC 准备/校验/调用、适配层、协程首段排队、提供方总时间
及正文序列化。**Git 内部监听器不进入发布包**，因此生产头部没有测试专用的
git_command_total / git_process。`*_total` 包含子阶段；多根/嵌套调用还可能重叠，勿全部相加。
异步操作只测提交阶段。头部在发送前生成，不包含随后的响应发送时间。
客户端总时间减去 http_read、http_parse、rpc_total、http_serialize，是未覆盖开销的合计，
包括认证/头部生成、传输及调度等，不能进一步冒充已实测的网络或 HTTP 队列成本。

80 对独立开关测试：关闭 P50/P95 为 **48.33/51.17 ms**，开启为 **48.44/50.98 ms**。
未观察到明显额外开销，不意味着所有环境的开销为零。
