# 0.6.2 文件枚举：实现、同条件复测与沙盒验证

日期：2026-10-24。先完成[优化设计](../design/file-enumeration-optimization.md)，再实现 `FileEnumeration` 并接入可选官方适配器。平台固定 IDEA 2026.2.3 / IU-262.10968.63、JBR 25.0.4、Gradle 9.1.0；语言与插件字节码仍为 Java 21。

## 实现与范围

`search_file` 的名称、schema、项目选择、官方动态筛选保持不变。明确目录 `paths` 加文件名 glob、`includeExcluded=false` 时，先在可取消的非阻塞读操作中枚举对应 IDEA 内容目录，复用官方路径/排除匹配。重叠目录和文件去重，不读取源码、不加载 PSI/AST、不保存编辑器、不缓存文件列表。

只返回完整且严格少于 limit 的结果。达到 limit（包括相等）、复杂正向范围、无明确目录、索引中、无法可靠解析目录、符号链接入口、包含排除文件或超过 200 ms 枚举预算时，交回原实现；不把未枚举完的结果报告为完整。原实现与快速路径共享 20 秒外层等待上限。完整结果无排序契约，差分核对完整路径集合；截断时仍使用官方前 N 项及 `more`/部分结果语义。官方 `execute_tool` 路由保留原实现。

官方 search_file 原本只返回官方项目目录内的文件。本次没有把项目外模块根加入它的范围，也没有缩小原生 Java 语义工具对这些模块根的支持。

## 同条件速度复测

本项目当前 **48 个 Java 源文件**复制为独立测试项目的冻结语料；每个文件保存 SHA-256，测试后与工作区逐一核对，48 项均一致。相较历史 0.6.1 测量的 46 个文件，增加了 `FileEnumeration.java` 和 `FileEnumerationTest.java`。三组在本轮使用完全相同的 48 个文件，不将新增源码遗漏出结果。

输入沿用之前的文件枚举任务：

```json
{
  "q": "**/*.java",
  "paths": ["src/main/java/**", "src/test/java/**"],
  "includeExcluded": false,
  "limit": 1000,
  "projectPath": "<同一个独立沙盒项目>"
}
```

先两轮预热，再三组各 20 轮，使用六种顺序交替。全部 **66 次**调用的完整路径集合一致、无重复、无部分结果。正式样本为 60 个，失败数为 0。优化后与官方提供方均返回相同字段和大小的完整结果（HTTP 响应 7,498 字符）；直接 rg 输出 2,372 字符，也包含相同的 48 个路径。

| 执行方式 | 中位数 ms | P95 ms | 完整文件数 |
| --- | ---: | ---: | ---: |
| idea-java 0.6.2，真实 HTTP / RPC 与优化后端 | **3.34** | **4.02** | 48 |
| 未优化的真实 JetBrains 提供方，相同 HTTP / RPC 外壳 | 15.73 | 19.68 | 48 |
| 不使用 MCP，直接启动 rg | 29.10 | 32.16 | 48 |

优化相对同条件官方提供方中位数降低 **78.8%**（约 **4.71 倍**），绝对减少 **12.39 ms**；P95 同时改善。满足设计中至少 20% / 2 ms 且 P95 不回退超过 10% 的启用门槛。

计时边界：使用 `System.nanoTime`；HTTP 组包含构造请求、传输、实际查询、响应解析及路径规范化；rg 组包含启动新进程、枚举、输出读取、退出等待及路径规范化。期望集合比较在计时后完成。两组 HTTP 使用同一客户端和相同服务器配置，不包含模型推理、工具发现启动或整个 Codex 调度。rg 通过 Java `ProcessBuilder` 启动，**不包含额外 PowerShell 启动**。

官方对照是固定 SDK 的真实工具实现，经相同测试 HTTP 外壳调用；没有冒称为官方独立 MCP 传输端点，也没有用生产 IDE 与沙盒的绝对耗时作直接比较。[历史 0.6.1 报告](0.6.1-speed-comparison.md)的 184 / 183 / 685 ms 来自当前聊天工具调度、生产项目和独立 PowerShell 调用，计时层及语料不同，不能用其减去本轮 3.34 ms 计算收益。此次未重测文本、正则、诊断等未修改的功能，也未对它们宣称提速。

原始数据在已忽略目录 `build/benchmarks/062-file-enumeration/sandbox.json`（输入、逐文件摘要、60 条样本）与 `summary.csv`。基准代码随 `FileEnumerationTest.testSameScopeHttpBenchmarkAgainstOriginalProviderAndRg` 保存。

## English summary

The 0.6.2 implementation follows the design written before development. It adds a conservative uncached complete-result path for explicit directory scopes, retaining the official glob/path helpers, tool filtering and fallback semantics. Limited results and router execution keep the original implementation.

In one isolated IDE with the same frozen 48-file corpus, two warmups and twenty alternating measured rounds per provider, all 66 results matched completely. Median/P95 latency was **3.34/4.02 ms** for optimized authenticated HTTP/RPC, **15.73/19.68 ms** for the real unmodified official provider behind the same HTTP/RPC wrapper, and **29.10/32.16 ms** for a directly launched rg process. The median improvement over the controlled official baseline is **78.8%**. These are not production Codex dispatch timings or measurements of the official standalone transport.

All **78 JUnit tests**, **94 protocol/HTTP assertions**, packaging and structure checks passed. A disposable Codex client discovered 0.6.2 and 73 sandbox tools and actually called the new enumeration path. At build completion, the user's installed plugin was still 0.6.1 with 77 production tools. The user subsequently installed/reloaded 0.6.2 and passed [production verification](0.6.2-installed.md). The ZIP and SHA-256 listed above are unchanged; no production service, breakpoint or database operation was performed.
