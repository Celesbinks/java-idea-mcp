# 0.6.8 目录树资格判断与独立沙盒验证

日期：2026-10-24；IDEA 2026.2.3 / 262.10968.63。先完成
[设计](../design/directory-tree-qualification-068.md)，再实现、差分和测量。

## 发布范围与未解决问题

只合入**目录密集、文件叶子少的形状判断**，保留普通文件宽根原有 NIO 路径。
自然宽目录 P95 没有稳定改善证据，不能将本包描述为已解决此问题。
Git 状态的源码、调度、参数和设置保持不变。没有安装或重启生产 IDEA。

最终资格判断仍要求根至少 32 项。完整缓存只作负向选择：根前 32 项至少 24 项
为目录时，最多检查 512 个已缓存可见节点，完整树文件/目录比小于 4 则走官方。
缓存不足不作结论。磁盘探测最多 32 个根名称、四个类型样本和四个目录分支，
总计最多 512 个名称；普通文件形状保留 NIO，目录形状只有在请求深度内观察到
256 个子项才保留 NIO。其他形状走完整官方遍历，不将名称探测当作输出。

输出独立读取全量属性、保留原身份/修改时间快照及最终校验；成功后直接返回完整
结果，不再因事后的文件数或密度重复调用官方。链接、变化、取消、异常、深度和
200 ms 候选预算/20 秒外层上限保持原有处理。不添加跨请求结果缓存。

## 未发布方案

- 初始逐项属性探测：冷自然目录中位数增加 1.78～1.92 ms，撤回。
- 128 文件门槛：127 文件已有约 2 ms 收益，强制回退使中位数恶化 45%～46%，撤回。
- 64 文件门槛：63 文件比旧版慢 0.58～0.94 ms，自然冷/热 P95 仍各一涨一跌，撤回。
- 首个名称方案的混合根误判已修正；深度资格测试改用 32 目录/256 文件，避免把
  冷大树必须在 200 ms 内成功作为断言。4096 文件仍独立进入性能实验，预算不扩大。

原始数据和失败日志全部保留在忽略目录 `build/benchmarks/068-qualification`：
prototype-attributes*、shape-v1*、threshold128*、threshold64*；最终为 sandbox.json、
summary.json、release.log。不删除慢样本或重试正式样本来改善统计。

## 公平性与完整性

在同一个独立 IDEA 测试 JVM、同一个项目、同一 HTTP/RPC/认证/计时包装和 JDK HTTP
客户端下比较：真实官方提供方、已发布 0.6.7 的目录算法、0.6.8 候选。
旧算法仅从发布 JAR 隔离加载 DirectoryTree 及其内部类，依赖使用当前 SDK；
反射仅存在于测试，不加载旧 IDE 服务。测试包内注入执行器以固定共同适配器路径。

12 个条件，每方预热 3 次，再取 84 次正式样本，独立两轮；第二轮反转条件顺序。
全部六种提供方顺序平衡使用，每方每个位置 28 次，每对先后各 42 次。
正式 **6048 个返回**，预热 **216 个返回**，共 **6264 次完整 MCP 对象比较**，
不只比较计数、正文前缀或截断页；官方结果要求 errors 为空。所有条件 maxDepth=100、
timeout=10000，三方均返回该范围下完整树。没有同时运行其他性能实验或构建。

自然夹具在新增测试编译前冻结，来自已安装 0.6.7 对照时的真实编译目录：
55 个直接子项、57 文件、59 个完整节点。cold/warm 仅指 VFS 是否预先完整加载，
不声称磁盘缓存冷启动。src 为当前源码快照，78 节点；大树为 32×128 文件、4129
节点；目录密集反例为 64 个目录各一个文件、129 节点；另测 63/64、127/128、255/256
和 1024 个平坦文件。每个条件内部三方查询参数、完整结果和作用范围相同。

下列是同层沙盒 HTTP 数据，不是已安装 0.6.8 的生产端点耗时；不能与 0.6.7
生产报告的绝对毫秒值混用。生产仍为 0.6.7，当前 Codex 目录与新包沙盒分别确认。

目录密集树相对旧版中位数下降 **57.9% / 58.3%**，P95 下降 **55.7% / 49.3%**。
相对直接官方仍多 0.416 / 0.295 ms 中位数，资格阶段 P95 为 0.641 / 0.629 ms；
此优化通过避免旧版不合适的 NIO 遍历获益，不宣称快于该任务的直接官方。

4096 文件大树相对官方中位数下降 **44.3% / 43.8%**，保留约 96～97 ms 收益；
相对旧版中位数为 -0.11% / +1.04%，P95 为 +0.64% / -0.60%，通过设计中的
5% / 10% 旧版回退上限及至少 20% / 2 ms 官方收益门槛。1024 文件也保留
46.8% / 46.9% 官方中位数收益，旧版 P95 差异为 -5.67% / +3.26%。
最终 336 个大树样本全部使用 NIO，未因预算回退；前一候选中的超预算慢样本仍保留。

自然冷根相对旧版 P95 为 +0.194 / -0.034 ms；热根为 +0.300 / -0.294 ms。
中位数变化不超过 0.092 ms，**没有稳定 P95 改善，普通宽根保持原路径**，
336 个自然样本全部仍走 NIO。资格阶段总 P95 为冷根 0.311 / 0.296 ms、
热根 0.318 / 0.326 ms；这不是相对旧版的净增加值。
小树 168 样本全部官方回退，资格阶段 P95 为 0.059 / 0.046 ms；总 P95
相对旧版仍增加 0.326 / 0.141 ms，不将总耗时波动全部归因为资格阶段。

撤回硬门槛后，63 文件中位数相对旧版仅多 0.007 / 0.052 ms，原先
0.58～0.94 ms 的断崖消除；63/64、127/128、255/256 全部 1008 个候选样本均走 NIO。
这不保证所有 P95 改善：127 文件第一轮 P95 仍比旧版多 1.264 ms（22.4%），
第二轮少 0.068 ms。完整分组、最大值和阶段分布保存在 summary.json，未合并两轮
或省略回退、离群值来掩盖尾延迟。

## 复现与建议

先在编译新增测试前冻结自然目录到 `build/benchmarks/068-qualification/input/natural`，
从已发布 0.6.7 ZIP 中提取自身 JAR（不是将 ZIP 作为参数）。然后执行：

```powershell
.\gradlew.bat "-PlocalIdePath=$env:IDEA_HOME" `
  -PdirectoryQualificationBenchmark=true `
  "-PbaselinePluginJar=<已发布0.6.7的自身JAR绝对路径>" `
  "-PcodexExecutable=<本机codex.exe绝对路径>" `
  test buildPlugin verifyPluginStructure --offline
```

不同时传 rgExecutable 或 directoryBenchmark，避免混入其他性能实验。
报告中毫秒值只用于同组同层比较；安装 0.6.8 后才能确认其生产表现。
自然宽目录暂保留现有路径，不继续调低文件数量阈值或引入结果缓存；后续若有新证据，
应先分开验证低成本形状判断与实际遍历固定开销，维持同任务、完整范围和生产/沙盒边界。
