# 调用树与 Git 状态性能设计（0.6.4）

状态：已完成。多仓库调度通过门槛进入 0.6.4；二进制 Git 处理器和调用树替换未采用。
最终数据及限制见[验证报告](../verification/0.6.4-query-performance.md)。下文保留先设计、后实验的决策依据。

## 问题与约束

0.6.3 已安装环境的公平复测中，完整 14 节点调用树的中位数 / P95 为
idea-java 781 / 900 ms、官方 766.5 / 863 ms；Git 状态完整 42 项为
68 / 127 ms、69.5 / 98 ms。两条路径目前均复用官方提供方，需区分提供方本身、
适配层和系统调度的成本。历史轮换顺序有偏的结果不参与决策。

查询参数、提供方授权、超时、范围、排序、歧义处理和完整输出必须一致。
不得减少树深度、忽略语言或重载候选、跳过引用、限制 Git 文件、用缓存替代实时结果。
不得改动用户仓库、IDE 服务或业务进程。新增实验仅使用独立测试 IDE 和临时仓库。

## 调用树

262 SDK 的分析器依次合并 QualifiedNameProvider、ChooseByName 符号搜索、
去参数名称搜索、所属类型中的可调用对象搜索，再创建 IDE 调用层次并展开和渲染。
即使 Java 精确名称已命中，跳过其他搜索仍可能遗漏歧义、多语言或依赖库符号。
分析器和可注入解析阶段不是公共扩展接口。

在沙盒中对完整官方查询、只渲染根节点和目标解析阶段计时；如需要反射，
仅用于测试定位，不进入插件运行代码。区分目标解析与层次展开，记录中位数、
P95、P99 和最大值。只有发现可在公共 API 边界减少重复工作且不改变候选集合的
方案才替换；否则保留官方调用树并交付可复现的定位结果。

## Git 状态

官方 VcsToolset 使用 GitRepositoryManager 选根、读取 IDEA 缓存的分支名，
随后通过 GitIndexStatusUtil 执行 `git status --porcelain -z`，解析完整状态，
先统计全部条目再应用 limit。初步怀疑 GitLineHandler 输出读取和进程等待是
尾延迟来源，尚需测量证明，不能把 CLI 与 MCP 传输耗时直接相减当作证据。

第一阶段比较相同临时仓库、相同参数的 GitLineHandler 与 GitBinaryHandler。
两者均须使用 IDEA 配置的 Git 可执行文件和环境，不自行解析用户配置。
优先复用 SDK 的参数构造、状态解析、GitFileStatus 判断和官方结果序列化。
如果只有私有解析器可用，不将反射或复制的版本绑定解析器加入生产路径。
再评估公开的进程处理扩展是否允许保留原命令与解析、仅改变输出读取策略。

安全边界：不在 EDT 等待 Git，不在 PSI 读锁中执行外部进程；取消和 20 秒
查询预算必须保持，取消只结束当前查询自己的子进程。不得缓存状态或分支，
不得绕过官方工具禁用、路由与确认设置。未知 Git 版本、缺失插件或不支持的
执行器退回官方实现。多仓库、外部根、子模块、worktree 和路径选择不得缩小范围。

## 验证与采纳门槛

### 实验后修订：多仓库调度候选

两轮 80 对实验中 GitBinaryHandler 与 GitLineHandler 的中位数分别为
54.0/53.4 ms、49.1/49.4 ms，未达门槛，停止生产实现。
小型调用树的完整 / 目标解析中位数为 35.6/31.7 ms；保留官方算法。

新的候选只优化至少两个独立 Git 根的调度：在每次查询中获取真实
GitRepositoryManager 根列表；仅对项目内、非符号链接、互不包含的 2～4 个根、
且没有显式 repositoryPathRelativeToProject 时启用。每根仍通过当前官方工具
独立查询，保持 includeUntracked/includeIgnored/limit，原样合并官方单仓库结果，
按官方根路径顺序返回。全局执行器最多四个工作线程，随应用服务卸载清理。
单仓库、嵌套根、外部根、大量根和显式选择均保留原官方实现。

提交前和完成后检查根对象、路径和分支快照；变化时丢弃批次并回退，不能混合。
仍在每个子调用中重新检查工具可用性、schema 和过滤设置。任何子错误均丢弃
全部结果并调用官方整批路径，以保留原错误格式；共享外层 20 秒截止时间，
超时或取消时取消本查询 Future，不能另开 20 秒回退。执行器不能占用 EDT，
不得在读锁内等待子查询。验收需加入完整四仓库官方差分与 80 对独立复测；
该优化不能宣传为当前单仓库项目加速。

1. 先差分完整 JSON / 文本，保留顺序、总数、所有计数、分支、重命名原路径、
   过滤标志和 limit 的含义；测试中文/空格/换行路径、暂存与未暂存混合、
   未跟踪/忽略、冲突、干净仓库及回退。不能用只比较节点数代替内容比较。
2. 相同 JVM / 项目 / 索引 / 仓库，预热后逐次执行，轮次奇偶决定先后方，
   每个任务双方各先执行一半；任务轮换与提供方顺序独立。不并行抢占被测资源。
3. 尾延迟正式样本至少每方 80 次，记录原始值、完整结果一致性、P50/P95/P99/max，
   再做独立复测。首轮冷启动另列，不混入热态样本。P99 在 80 样本中接近最大值，
   不据此声称稳定的总体分位数。
4. 启用门槛沿用既有设计：中位数改善至少 20% 且至少 2 ms，P95 不恶化超过 10%。
   只有实验成功且端到端差分通过的部分进入默认实现；未达门槛的候选删除。
5. 沙盒验证取消、超时、卸载/过滤与完整结果，跑受影响测试及发布检查，生成
   0.6.4 安装包。安装环境仍为 0.6.3，升级后才可声称验证生产中的新实现。

线程约束参考 [JetBrains Threading Model](https://plugins.jetbrains.com/docs/intellij/threading-model.html)，
状态协议参考 [git-status](https://git-scm.com/docs/git-status)。SDK 行为以当前
262.10968.63 实际提供方和差分结果为准。
