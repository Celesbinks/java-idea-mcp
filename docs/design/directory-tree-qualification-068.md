# 目录树按可见文件规模判断优化资格（0.6.8）

日期：2026-10-24。先设计，再实现和比较。Git 状态实现、参数、调度及设置保持不变。
目标 IDEA 262.10968.63，生产仍为 0.6.7，不将候选安装到生产 IDE。

**发布决定：只合入目录密集、文件叶子少的选择优化。** 下文保留实现前方案及实测
收敛记录；最终算法见“发布收敛”一节。普通文件数量门槛均已撤回，自然宽目录
P95 没有稳定改善证据。不会将未通过的资格方案作为已完成的性能修复。

## 问题与验收目标

[0.6.7 生产复验](../verification/0.6.7-installed.md)发现，55 个直接子项、59 个完整节点的
自然宽根虽有资格进入 NIO，但没有稳定中位数收益，HTTP P95 增加 0.282～0.353 ms。
32 个目录/4096 文件的受控大树则稳定获益。仅比较根宽度不能抵消真实路径/身份检查、
目录快照和属性读取的固定成本，也没有考虑 maxDepth 内实际返回多少文件叶子。

新方案必须让小规模宽根走真实官方遍历，保持大树的完整结果和既有收益。
两轮对照旧 0.6.7、当前官方提供方与候选，不使用端点不同的固定成本证明资格判断有效。
自然目录的目标是降低相对 0.6.7 的 P95 且不造成中位数明显回退；绝对改善仍按毫秒报告，
不套用旧大树 2 ms 门槛掩盖本次约 0.3 ms 问题。大树必须保留至少 20% / 2 ms 的官方
基线中位数收益，且相对旧版本中位数回退不超过 5%、P95 不超过 10%。

## 初始资格方案（实验未通过，不发布）

保留根至少 32 项、maxDepth 2～100、现有参数与官方错误/取消处理范围。额外要求：

1. **请求深度内至少 256 个可见普通文件**，并且已观察的文件数至少为目录数的四倍。
   目录本身和 maxDepth 之外的子孙不当作文件收益；目录密集但少文件的树保留官方。
2. 非阻塞短读动作只查已经缓存、完整加载的 VFS 子树。若能证明可见文件不足 256，
   直接走官方磁盘遍历；遍历最多 512 个缓存节点，不加载、不刷新、不在读锁中做 IO。
   缓存不完整或无法立即取得锁，不作“文件很少”的结论。陈旧的负向判断只少启用优化，
   从不据 VFS 生成返回树或缩小磁盘查询范围。
3. 未能负向判断时，在真实磁盘中做有界资格探测：最多观察 512 个节点，达到文件与
   目录比例条件即停止；不足条件、复杂类型/链接、预算用尽均回退官方。
   不按 .class 等扩展名猜测类型，不额外启动 Git、rg 或其他进程。
4. 复用本次探测得到的目录快照、完整/部分子项和属性；完整列表直接用于渲染，部分
   列表重开时只补齐未观察的项。目录身份和修改时间覆盖从首次探测到最终完成的窗口，
   不能在渲染时重置快照掩盖中间变化。正向缓存也不能当作真实磁盘结果。
5. 探测与渲染共享现有 200 ms 候选预算及请求余量，保留 20 秒外层等待。超时回退
   不返回部分成功，实际取消/中断不吞掉。输出排序、缩进、字段、节点、深度、错误
   与官方一致；资格只选择执行实现，不是结果上限。新增请求内阶段按需观测，不记录路径或输出。

阈值是待验证的保守成本条件，不保证所有大树都能优化。未知或目录过密的形状宁可
走官方，不为扩大资格去降低门槛。小冷根额外探测成本与热缓存情况分开测量。

## 实验与完整性

先冻结当前自然目录的完整磁盘快照，再编译新测试，避免新增匿名 class 改变对照规模。
记录每个 fixture 的文件/节点数和完整树，比较全 MCP 对象及文本，不只比较计数。

独立沙盒使用相同项目和同一个 HTTP/RPC 包装比较三方：真实官方提供方、从已发布
0.6.7 JAR 加载的原目录算法、新算法。旧算法反射/隔离类加载仅在测试中使用；生产
只提供默认新实现。适配器允许包内注入目录执行器以固定共同分派路径，不改变工具目录。

条件包括：src 小根、自然 55 项宽根的冷/热 VFS、平坦 255/256 文件边界、32×128
完整大树、平坦大树、浅深度和目录密集反例；每条件三方至少预热 3 次，正式 80 次，
采用全部六种提供方顺序平衡先后（正式数量可提高到 84 以整除六种排列），独立两轮，
第二轮反转条件顺序。不并发构建或其他基准，不删离群值、重试或混合层次统计。
对长批次单独设置测试框架等待，不改工具单次等待上限。

重点测试资格不足、256 边界、深度边界、不完整/陈旧 VFS、未刷新磁盘文件、链接/junction、
取消、超预算和探测快照重用；复用已有真实官方禁用、router-only、查找后替换/移除测试。
最终运行完整独立沙盒、外部临时 Codex、协议/HTTP 自检及 buildPlugin/verifyPluginStructure。
版本同步为 0.6.8，保持 Java 21 字节码和原兼容范围，交付 ZIP 与 SHA-256。

生产连接只做已安装版本的只读确认，不把旧服务的结果当作 0.6.8 生产收益。若某个资格
原型不达标，保留数据并撤回或收紧，不为生成安装包强行宣称性能改善。

## 最终资格方案（首轮实验后、第二版实现前确定）

首轮 4032 个正式样本证明：逐项读取属性的资格探测会在冷自然树增加
1.78～1.92 ms，中位数回退约 50%；255 文件其实已有稳定 NIO 收益，不应在 256
处制造回退断崖。该原型不发布，原始记录保留在忽略目录。

第二版先做只枚举名称的有界形状探测，探测结果只用于选择，绝不用于生成输出。
平坦根至少 128 项且前四项中能观察到普通文件才候选；较窄根必须在请求深度内、至多四个
直接子目录的名称枚举中观察到合计 256 项。遇到文件混排或未知形状提前放弃，
允许漏掉可优化树，不允许漏掉输出。名称总量限 512，深度不足时不探测后代。
探测只为检查少数分支读取属性，不逐文件重复 stat，不复用不完整名称列表。
超过样本数量或目录混排的不确定形状直接回退，不扩大探测。大部分普通文件混合少量
目录的根不应仅因首项是目录而失去资格，因此允许最多四项类型抽样。浅层请求同样
允许这个平坦判断；目录分支探测则必须保证其子项在 maxDepth 以内。
后续仍执行完整 NIO 属性遍历，实际普通文件必须至少 128、文件/目录比例至少 4；
快照从实际输出遍历开始，到最终校验结束。选择阶段与输出阶段没有混合缓存。
已有 255 文件收益保留；新增 127/128 边界验证。相同三方两轮实验重新验收。
名称探测与输出遍历共享原有 200 ms 预算；任何预算回退都保留在性能样本中。
深度资格用 32 个目录/256 个文件验证，4096 文件独立进入性能对照；不能要求冷大树
无条件突破既有 200 ms 预算。初始深度测试在此预算处返回官方，属于断言范围不当，
不通过扩大生产预算或删掉正式慢样本解决。

最终发布只宣称观察到的收益。自然目录与官方回退的总耗时接近时，必须同时披露
两轮 P50/P95、额外资格耗时和不稳定性；不能将目录密集树的收益冒充自然宽目录收益。
对任意深层或混排树不保证启用优化；回退仍返回完整官方结果。

## 阈值校准（最终 128 门槛实验后、64 门槛实现前）

两轮完整三方实验揭示 127 文件具有 2.0 ms 以上的既有收益；128 硬门槛使此任务
相对旧版中位数回退 45%～46%，不接受该断崖。改为 64 个实际文件的保守下限，
同时把根名称探测上限从 512 收到 64；目录分支仍保留 256 个子项与四个目录限制。
自然夹具的 55 直接项/57 文件仍被排除，127/128 和更大平坦树保留资格。
补测 63/64、127/128、255/256 全部边界，所有原型数据保留。阈值调整只减少
已知无收益资格和额外名称遍历，不提高查询范围或修改输出。总探测仍不超过 512 名称。

## 发布收敛：只保留有明确收益的目录密集判断

64 门槛复测仍使 63 文件退步 0.58～0.94 ms，自然冷/热树的 P95 仍各一涨一跌。
两种普通文件数量硬门槛均不发布。自然目录的问题没有证据证明已解决，不为交付
强行保留普通宽根的负向判断。最终保留已有普通宽根路径，只拒绝低叶子密度形状：

- 缓存根前 32 项至少 24 项为目录时，至多检查 512 个已缓存可见节点；完整缓存树
  的文件/目录比小于 4 才负向选择。不完整/超界缓存不作结论，不能用于返回输出。
- 磁盘只探测根的前 32 个名称。首项普通文件直接保留原 NIO；首项为目录则最多
  抽样四项，遇到普通文件仍保留 NIO。全为目录时，在请求深度内最多读四个分支、
  总计 512 名称；观察到 256 个子项即可保留 NIO，否则选择完整官方结果。
- 资格阶段不逐文件 stat，不缓存跨请求结果。输出遍历独立读取完整属性和快照，
  成功后直接返回其完整结果，不再因事后的文件数或密度检查重复跑一遍官方。
- 保留 31/32 根宽度及 63/64、127/128、255/256 性能对照，明确验证被撤回硬门槛
  引起的回归已消除；两轮完整对照大树。自然树保持原路径，不宣称 P95 被修复。

## English (release scope)

Keep Git unchanged. Attribute-heavy probes and both file-count thresholds failed validation
and are not released. Keep ordinary file-first wide roots on the existing NIO path. Select
official traversal for directory-heavy, low-leaf shapes using complete bounded cached VFS
information or a 32-name root / four-branch / 512-total-name disk probe. Results still come
from a fresh complete traversal with the original snapshots. Do not claim that natural-wide
P95 has been fixed; release only the independently demonstrated directory-heavy benefit.
Compare official, released 0.6.7 and candidate under one wrapper, with balanced repeated runs,
cold/warm small-wide cases, full-result checks, independent sandbox and release validation.
